# 国际结账基础

本阶段为一笔报价对应一笔定制订单建立结账确认边界。它不是购物车，也没有连接 Stripe、PayPal、微信支付、支付宝或其他外部服务。

## 已实现

- 报价被客户接受后进入“待确认结账”，客户必须确认订单金额、联系信息和收货信息，订单才进入待支付状态。
- 每个订单保存一份私有地址快照：收件人、邮箱、电话、ISO 两字母国家或地区代码、州/省、城市、详细地址和邮编。
- 客户订单、地址和付款记录均通过登录用户和订单所属客户做对象级授权；这些数据不进入公开 API。
- 后端以 `Decimal` 计算服务小计、运费、税费、折扣和最终应付总额：

  ```text
  最终应付总额 = 服务小计 + 运费 + 税费 - 折扣
  定金 + 尾款 = 最终应付总额
  ```

- 订单币种是创建时确定的 ISO 4217 代码，目前只接受 `CNY` 和 `USD`，不换汇。
- 结账接口只接受地址字段，不接受客户端传入的金额、币种、定金或尾款。事务和行锁保证重复确认不会重复改变状态。
- 现有模拟付款仍只在后端明确开启、开发环境且客户与订单均标记为开发数据时可用；生产配置返回 403。
- 中英文界面共享同一个表单状态，切换语言不会重建页面、清空地址或改变路由。
- Django Admin 可查看金额构成、结账状态和国家/地区；付款审计字段保持只读。

## 历史数据兼容

迁移不会删除或批量改写客户内容。旧订单的原订单总额会安全映射为服务小计，其他金额构成默认为零。迁移前已经接受的历史报价保持原有可付款状态并标记为已确认结账；地址允许为空，因此历史订单不会失效。

## API

登录客户在接受本人有效报价后可调用：

```http
POST /api/v1/me/orders/{order_id}/checkout-confirmation
```

请求只包含联系和地址字段。重复提交已确认订单返回当前结果，不新增地址或付款记录。未登录、工作人员代操作或访问其他客户订单会被拒绝。

## 支付提供方扩展边界

订单核心只负责金额、结账、付款状态和付款审计记录。未来真实支付适配器应在服务层实现统一的“创建支付意图、验证异步通知、查询、退款”契约，并把渠道交易号和幂等键映射到 `PaymentRecord`，不能让提供方请求直接修改订单。

接入任何真实渠道前仍必须完成：

- 商户账号、主体认证和密钥的独立密钥管理，绝不写入前端或 Git；
- 服务端回调验签、时间戳/重放防护、订单金额和币种二次核验；
- 创建、回调、退款各自的幂等键以及并发记账保护；
- 部分退款、全额退款、失败和争议状态设计；
- 每日对账、异常订单告警和人工审计流程；
- 汇率来源、锁价时点和舍入规则（启用换汇时）；
- 运费、关税、销售税/增值税和发票责任；
- 地址、支付标识、日志留存和跨境数据传输的隐私合规；
- 沙箱测试、密钥轮换、故障降级和正式上线审批。

## 明确未实现

- 真实支付请求、Webhook、退款、对账或支付 SDK；
- 自动汇率换算、税率计算、承运商报价或地址第三方校验；
- 购物车、多商品订单、库存或优惠券系统；
- 部署、远程数据库或外部服务连接。
