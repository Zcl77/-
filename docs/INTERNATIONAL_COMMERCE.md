# 中英文与国际化交易基础

## 当前能力

前端支持简体中文 `zh-CN` 与英文 `en`。语言入口位于桌面和移动导航，选择保存在浏览器 `localStorage`；首次访问参考浏览器语言，无法识别时使用简体中文。固定界面文本集中在 `src/i18n/index.tsx`，缺失英文翻译时安全回退到中文源文本。日期、数字和金额由当前语言的 `Intl` 格式化，金额计算仍由后端使用 `Decimal` 完成。

前端发送 `Accept-Language`，公开 API 在不改变字段名和路径的前提下返回对应语言内容。以下公开内容可在 Django Admin 独立维护中文与英文：

- 作品分类名称与说明；
- 作品标题、摘要、正文、比例、尺寸、材料、周期、作者；
- 作品图片替代文本、说明与空间名称；
- 公开制作日志标题、摘要、正文及图片替代文本、说明；
- 工作室标语、介绍和隐私说明。

英文字段均可为空；为空时 API 返回现有中文内容。迁移不会翻译、覆盖或批量改写任何现有内容。客户项目、项目留言、询价与评价等用户提交的动态正文暂不自动翻译，它们按录入语言原样显示，避免虚构或机器翻译业务内容。

## 交易扩展边界

订单与付款记录使用 ISO 4217 货币代码，目前数据结构支持 `CNY` 与 `USD`。现有 CNY 报价、定金和尾款流程保持不变；系统不执行汇率换算，前端也不能提交或计算应付金额和币种。

`backend/projects/payment_providers.py` 定义未来真实支付提供方的最小协议：创建付款、退款和回调验签。当前工厂始终拒绝返回真实提供方，不创建网络请求。现有 `mock` 渠道仍只允许开发环境中明确标记的开发客户和开发订单，并继续只支持 CNY。

## 接入真实支付前必须完成

未来接入微信支付、支付宝、Stripe 或 PayPal 时，需要单独设计、审查和验收以下工作：

- 申请并验证商户账号，在服务端密钥管理系统保存凭据，绝不提交到 Git 或发送到浏览器；
- 为每个渠道实现服务端订单创建、回调签名验证、时间戳与重放防护；
- 对创建付款、回调、退款建立数据库级幂等键和并发锁，不能只依赖前端按钮状态；
- 建立退款审批、部分退款、失败重试、争议与异常订单处理流程；
- 定期进行渠道账单、银行入账和内部付款记录的对账，并保留不可篡改的审计记录；
- 明确报价货币、结算货币、汇率来源、锁价时点和汇兑差额；
- 根据销售地区处理税费、发票、消费者保护、退款政策和会计要求；
- 完成隐私告知、数据最小化、跨境传输、保存期限、访问控制和日志脱敏评估；
- 在隔离测试环境验证成功、失败、超时、重复回调、乱序回调和退款全流程后再考虑生产启用。

本阶段不包含任何真实支付 SDK、商户资料、密钥、外部连接或部署配置。
